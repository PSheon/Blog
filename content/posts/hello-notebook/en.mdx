Every article on this blog is a folder containing `zh.mdx`, plus `en.mdx` when there is an English version. Interactive components live in the same folder under `components/` and are imported by the article itself, so an article's code is loaded only on that article.

## Body text

The body is set in a serif face at a measure of about 68 characters, with generous line height so long pieces are easier to read. **Bold** marks a term on first use, *italics* add emphasis, and `inline code` is for identifiers. Links look like [this](https://nextjs.org).

Sidenotes hold things that are worth saying but would interrupt the argument.<Sidenote>Like this. On a wide screen it sits in the right margin, level with the line that cites it. On a phone, tapping the number opens it inline.</Sidenote> Write so that the main text still reads well without them.

## Code

Code blocks are highlighted by Shiki, with one palette per theme. They can carry a filename and highlight lines:

export function relu(x: Tensor): Tensor {
  const out = zeros(x.shape);
  for (let i = 0; i < x.data.length; i++) out.data[i] = Math.max(0, x.data[i]);
  return out;
}

## Maths

Inline maths looks like $\mathrm{softmax}(z)_i$, and display maths is centred:

$$
\mathrm{softmax}(z)_i = \frac{e^{z_i - \max(z)}}{\sum_j e^{z_j - \max(z)}}
$$

Subtracting $\max(z)$ doesn't change the result, but it stops $e^{1000}$ from overflowing.

## The instrument frame

Every interactive sits in the same frame: a monospaced title bar, a dot-grid stage and a caption. The frame includes an error boundary, so if a component breaks, the rest of the article stays readable.
