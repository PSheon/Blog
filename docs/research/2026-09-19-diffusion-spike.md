# № 007 擴散模型：可行性 spike

2026-09-19 · main session。果蠅那篇結案之後，Paul 選了「在瀏覽器裡訓練一個擴散模型，看雜訊變成圖」，並問能不能做成 3D 點雲。

## 結論

**可行，而且整個訓練可以在讀者的瀏覽器裡發生。** 不需要離線預訓練、不需要新的相依套件（Three.js 已經為 Lite3 裝了），`lib/ml` 現有的 `matmul`／`addRow`／`relu`／`mse`／`Adam` 就夠用。

## 做法

資料的一筆 = 形狀表面上的**一個 3D 點**，不是一整張圖，所以模型很小。DDPM，100 個雜訊等級，cosine 排程；網路是 MLP（輸入 29 維：座標、座標的 3 組正餘弦、雜訊等級的 4 組正餘弦 → 64 → 64 → 64 → 3），10,435 個參數，預測被加進去的雜訊。取樣用 DDIM（η = 0），40 步，3,000 個點一起走。

## 量到的東西

| 項目 | 結果 | 在哪裡量的 |
| --- | --- | --- |
| 訓練速度，隱藏層 64 | 280 步／秒（batch 256） | Node，M 系列；`diffusion-spike/probe.test.ts.txt` |
| 訓練速度，隱藏層 64 | 275–293 步／秒，同時每個畫面還做一步 3,000 點的取樣 | Chrome，同一台機器，dev build |
| 訓練速度，隱藏層 128（37,251 個參數） | 84 步／秒 | Node |
| 品質（三葉結，Chamfer 距離；資料對資料的下限是 0.042） | 1 秒 0.111 → 8 秒 0.093 → 21 秒 0.078（隱藏層 64）；72 秒 0.068（隱藏層 128） | Node |
| 取樣 1,500 點 × 25 步 | 0.21 秒（隱藏層 64），也就是一步約 8 ms，可以當動畫播 | Node |
| Lite3 點雲 | 8,000 個表面點，int16，48 KB | `diffusion-spike/make-dog-points.test.ts.txt` |

眼睛看到的：訓練 5 秒是一團有上下之分的雲；30–40 秒看得出機身、四條腿和膝蓋。腿的點原本太少（按面積取樣，機身佔了八成），把腿的取樣權重調成 2.5 倍之後才清楚。

## 已知的問題

- 點雲還是毛的，離「乾淨的表面」有距離。隱藏層加寬到 128 有幫助但慢 3.4 倍；還沒試 SiLU、殘差、更長的訓練、或對取樣結果做 x̂₀ 的截斷。
- 相機距離是寫死的：Lite3 剛好，三葉結和圓環會超出畫面。
- 只在桌機 Chrome 看過深色主題；手機、淺色、`prefers-reduced-motion`（已接上，沒看過）都還沒驗。
- 三葉結和圓環只是為了量數字，文章要用什麼形狀還沒決定。

## 改成水果和風景，而且連顏色一起學（同一天，Paul 的要求）

Paul 不要機器狗，要水果或風景。Lite3 的點雲和它的取樣腳本已移除。現在每個點是 **6 個數字：x, y, z, r, g, b**，模型同時把位置和顏色從雜訊裡還原出來，所以蘋果是紅的、葉子是綠的，這是學到的，不是畫上去的。形狀全部是程式產生的（`components/shapes.ts`）：蘋果（心臟線繞軸旋轉，自帶凹陷，加梗和葉子）、香蕉、葡萄、西瓜切片（紅肉、黑籽、白邊、綠皮條紋）、風景（兩座雪山、草地、湖、八棵樹、太陽）。不需要任何資產檔。

網路加寬到 96（輸入 32 維，輸出 6 維）。在 Chrome 裡量到 **146–150 步／秒**（同時每個畫面取樣 3,000 點），訓練 45 秒約 4,000 步：

- **蘋果**：形狀、紅到黃的漸層、綠葉都出來了；梗不清楚。
- **西瓜**：綠皮、白邊、紅肉三層都對；籽太細，看不出來。
- **風景**：看得出綠色的地面、遠處灰白的山和一團黃色的太陽，但山的輪廓糊、太陽縮成一小團、湖和樹幾乎看不出來。風景的細節多、又分散，這個大小的網路在 45 秒內不夠；要嘛訓練更久／網路更大，要嘛把風景設計得更大塊。
- 香蕉和葡萄只看過目標形狀，還沒看過學出來的樣子。

## 正式頁面（同一天）

Paul 決定只做水果，並選了「選兩種水果一起長」這個點子。`content/posts/diffusion-points` 現在是一篇完整的中文草稿加三個儀器，共用一個模型（`components/store.ts`）：

- **01 train**：選兩種水果（蘋果、香蕉、葡萄、西瓜、橘子），訓練；三團點雲不斷從新的雜訊重新取樣：左、右各一種，第三團是混合，滑桿控制條件向量 `[1−t, t]`。
- **02 add noise**：前向過程，沒有模型，滑桿把一顆水果埋進雜訊。
- **03 40 steps**：用讀者自己的模型取樣一次，存下 41 個畫面，可以前後拖。

模型變成**有條件的**：輸入多兩個數字（要哪一種水果），共 22,566 個參數（隱藏層 96）。換一對水果會重建模型。

量到的（Chrome，M 系列 Mac，dev build）：只算訓練時間是 138–151 步／秒；牆上時鐘約 80 步／秒（每個畫面只給訓練 8 ms，其餘留給 3,300 個點的取樣和繪圖）。訓練 5 秒顏色分開，10 秒看得出形狀，30 秒蘋果的葉子清楚。混合那一團在「蘋果＋香蕉」時長成蘋果形狀、香蕉顏色、帶葉子的東西，這是一次的觀察，不是保證。

決定：點雲畫面在深淺兩種主題下都用深色底（黃色的點在白底上幾乎看不見）；手機上三團排成三角形而不是一列。測試：`tests/diffusion/diffusion.test.ts`（排程、水果範圍、兩種水果各自長對）和 `e2e/smoke.spec.ts` 裡的一個測試（草稿在 production build 會跳過，對 dev server 跑過，桌機和手機都過）；axe 對草稿單獨掃過，兩種主題都沒有違規。

還沒做：en.mdx、真機手機、`prefers-reduced-motion` 實際看過（已接上：不旋轉，但取樣動畫還是會動）、取樣動畫的暫停鍵。
